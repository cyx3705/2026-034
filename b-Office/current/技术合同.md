# HistoryStrenua 技术合同

本文件合并当前有效的需求与架构。关键决策单独保存在 `有效决策.md`；已失效内容移入
`../history/`，不得继续作为实现依据。

## 现行需求

### REQ-001 快捷指令登记表

- 目的：PowerSW 会持续加快捷指令，加一条不应改页面描述、动作声明和指令注册三处。
- 要求：每条快捷指令是一条 `QuickCommand`（键、指令名、标题、摘要、用法、执行体），登记在
  `QuickCommands.All`。控制面板按钮（1.7.0，按命令类分面板）、类选项（命令类 → 类名，`QuickCommands.ClassTitle`，
  `hole` → 「孔」）、动作声明（`strenua.quick.<键>`）、总线指令全部由登记表生成。目前都不带参数；将来带参数时在
  `QuickCommand` 上加参数表，由页面生成器渲染成输入控件并经动作占位符传入，已有无参指令不受影响。
- 验收：离线用例「buttons, actions and commands line up」「class panels: buttons and switches」「list rows」。
- 关联组件：`b-Code/HistoryStrenua/QuickCommand.cs`、`StrenuaPage.cs`、`HistoryStrenuaModule.cs`
- 关联验证：`VERIFY-UNIT`

### REQ-002 附着而不接管

- 目的：PowerSW 作用于用户手上的 SolidWorks，任何「顺手」的接管都会打断用户。
- 要求：只经运行对象表附着已运行的 SolidWorks（`GetActiveObject`），没开就失败并说明；
  不改 `Visible` / `UserControl`、不 `ExitApp`；收工只释放本次经手的 COM 引用。
  一次只跑一条快捷指令（它们共用同一个选择集），第二条直接回执「还在执行」。可取消。
- 验收：VERIFY-LIVE 第 1、5 步。
- 关联组件：`b-Code/HistoryStrenua/SolidWorks/`、`QuickCommandRunner.cs`
- 关联验证：`VERIFY-LIVE`

### REQ-003 孔标注

- 目的：给工程图视图里的孔逐个加孔标注是纯重复劳动。
- 要求：
  1. 活动文档必须是工程图。当前选择里有视图（或视图里的任何对象）就用它；否则等用户点选，最多 60 秒。
  2. 孔的判据是几何：整圈圆边（无端点）、旁边有一张**内凹**且同半径的圆柱面、轴线正对图纸
     （视图空间里与法向夹角余弦 ≥ 0.999）。内凹 = 面法向指向轴线：在圆上取点求曲面法向，
     再按 `FaceInSurfaceSense`（**true 表示面法向与曲面法向相反**，见 DEC-005）换算成面法向。异形孔向导的各类孔与手工切出的圆孔都算；
     开口槽口端部半圆、凸台外圆、侧视投影不算。腰型孔见 REQ-007。
  3. 装配视图逐个可见组件取边，几何先乘组件变换再乘视图的模型→图纸变换。
  4. 图纸上圆心相距不到 0.02 mm 的圆边算同一个孔（沉头与底孔、通孔上下口），取半径最小的那条。
  5. **每种孔只标一次**：一种 = 同一组件、同一特征（孔壁所属特征）、同一孔径。SolidWorks 的孔标注会自己写上
     「N×」，每个都标就是同一行字重复 N 遍。标在这一种里最靠左上的孔上。
  6. 一种孔里只要有一个已有孔标注，整种跳过。新标注放在孔的**左上方**（1.1.0 起，DEC-008）：引线折点（文字下划线右端）
     在孔心左上 45°、离孔心「孔半径 + 12 mm」，文字从折点往左排，引线斜向右下指到孔。文字多宽生成后才知道，
     所以先落位、再读显示数据里最长的水平线（下划线）的右端，平移整个标注对准，最多挪三次、偏差 0.1 mm 内。
  7. 回执说明认出几个孔共几种、新加几个、跳过几种、SolidWorks 拒绝几个；确有要加的却一个都没加上时回执失败。
- 验收：离线用例覆盖合并、分种、跳过、排序、放置（左上）、下划线右端识别、正对判定、孔壁判定；真机见 VERIFY-LIVE。
- 关联组件：`b-Code/HistoryStrenua/HoleCallout.cs`、`HoleCalloutPlanner.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-005 中心符号线（1.1.0）

- 目的：给视图里的孔一个个插中心符号线、再连成组是纯重复劳动；旧的单个中心符号线也要一个个删。
- 要求：
  1. 取视图、认孔、同心合并、分种与 REQ-003 第 1–5 条完全相同（共用 `HoleScan` 与 `HoleCalloutPlanner`）。
  2. **重新标记**：先删掉标着这些孔的旧中心符号线——孔心取它附着的圆边，附着丢失时取它自己记的位置过视图变换；
     一组里只要有一个孔心落在孔上整组删。不在孔上的中心符号线（圆角、开口槽口）不动。删完回读，最多删三遍
     （真机上第一遍偶有漏删）；仍有删不掉的就失败、不重标。
  3. 每种孔一组：两个孔以上用 `InsertCenterMark3(swCenterMark_LinearGroup)`，再把 `ConnectionLines` 设为
     `swCenterMark_ShowLinearConnectLines`——即中心符号线属性里手工插入的第二种「线性中心符号线」勾连接线；
     只有一个孔的种用单个中心符号线。组内孔按图纸上从上到下、从左到右选；SolidWorks 不接受线性组时退回逐个单个。
  4. 回执说明认出几个孔共几种、删掉几个旧的、新加几组线性、几个单个、几个没接受；一个都没加上时回执失败。
- 验收：离线用例「center marks: one group per kind」「center marks: only marks on holes are redone」；真机见 VERIFY-LIVE。
- 关联组件：`b-Code/HistoryStrenua/CenterMark.cs`、`CenterMarkPlanner.cs`、`HoleScan.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-006 孔位尺寸（1.2.0）

- 目的：给视图里的孔逐个标位置尺寸、同一行一排孔再算阵列文字是纯重复劳动。
- 要求：
  1. 取视图、认孔、同心合并、分种与 REQ-003 第 1–5 条完全相同（`HoleScan` 另收集视图里的直边）。
  2. **基准**：视图里最左的竖直直边（左侧基准）与最上的水平直边（上侧基准）；同一位置有几条取最长的。找不到就失败。
  3. **每个方向、每种孔单独标**（DEC-009）：这一种里的孔按坐标归成中心线（水平方向按 X 归列、竖直方向按 Y 归行）；
     第一条从基准标，其余接着前一条标（同种孔可接着前一个孔标，不同种孔必须从基准标）。
  4. **阵列标法**：同种孔一个方向超过 4 条中心线且等距（间距差 ≤ 0.01 mm，模型尺寸）时，基准到第一条一个尺寸、
     第一条到最后一条一个尺寸，前缀 `IDisplayDimension.SetText(swDimensionTextPrefix, "(N-1) x 间距 =")`，
     值由 SolidWorks 给出总长；间距按模型 mm 取两位小数去尾零。不等距退回第 3 条的链式。
  5. **按中心线标、不按孔标**（DEC-010）：同一段「中心线 → 中心线」（含基准到中心线）在一个方向上全视图只标一次。
  6. 选择：水平尺寸的孔那一头在孔心按 `CENTERMARKSYMS` 点选中心符号线，核对选中类型为 100，SolidWorks 把尺寸连到
     符号线的竖线（`swSelEXTSKETCHSEGS`）；有一头选不到就整条改选孔边。竖直尺寸只选孔边（DEC-010）。建出来的
     `Type2` 不是线性（2/11/12）就删掉、改选孔边重建。
  7. 放置：水平尺寸在上侧基准之上、竖直尺寸在左侧基准之左；一种孔一层，第一层 8 mm、层距 6 mm（图纸），
     跨度短的在里；阵列那一种阵列尺寸在里、基准尺寸在外。没分到尺寸的种不占层。不避让相邻视图。
  8. **重新标**：先删连着这些孔的旧线性尺寸——附着孔边且圆心在孔上，或附着视图草图线且线段穿过孔心
     （草图点 → 图纸：视图位置 + 草图点 × 比例；视图旋转过则不认草图线）。孔标注、非线性尺寸、不连孔的尺寸不动。
     视图里**悬空**的线性尺寸（`IAnnotation.IsDangling`，或附着对象为空 / 类型 0）也一并删（1.3.0，DEC-012）。
     删法同 REQ-005 第 2 条（`AnnotationEraser`）。
  9. 回执说明认出几个孔共几种、删掉几个旧的、新加几个（阵列几个、连在中心线上几个）、几个没接受；
     有要加的却一个都没加上时回执失败。
  10. **尺寸链模式**（1.7.0，DEC-018，页面「尺寸链」开关，默认关）：第 3–5、7 条换成——每个方向只有一条链，
      基准 → 第一条中心线 → 第二条 → … → 最后一条，不分孔的种类；同一条中心线上几个孔（不论哪种）算一站，取离尺寸最近的那个孔
      （水平取最上、竖直取最左）；等距也逐段标，不用阵列写法；全排在第一层（8 mm）。其余（基准、选择、重新标、避障）不变，
      回执里「阵列标法 P 个」换成「尺寸链模式」。
- 验收：离线用例「hole position: …」7 组（含 chain mode）；真机见 VERIFY-LIVE 第 8–10 步。
- 关联组件：`b-Code/HistoryStrenua/HolePosition.cs`、`HolePositionPlanner.cs`、`AnnotationEraser.cs`、`HoleScan.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-007 腰型孔兼容（1.3.0）

- 目的：板件上的腰型孔（长圆孔）与圆孔一样要标孔标注、中心符号线和位置；1.2 以前端头半圆被当成槽口排除，腰型孔一个都不标。
- 要求：
  1. **认端头**：圆弧有端点时，两端点中点落在圆心上（偏差 ≤ 半径 × 0.001）才算恰好半圈；孔壁、正对判据与 REQ-003 第 2 条相同。
     鼓出方向：弦法向 n = 轴 × 弦，在「圆心 + 半径 × n」处取圆弧上最近点（`IEdge.GetClosestPointOn`），离得近（< 半径/2）
     鼓向 n，否则鼓向 -n；变到图纸平面后归一。
  2. **配对**（`SlotPlanner.Pair`，在同心合并之后）：同种（组件 + 特征）、同半径（差 ≤ 0.02 mm 图纸）、两圆心连线上
     A 背着 B 鼓且 B 背着 A 鼓（夹角余弦 ≥ 0.999）；有几种配法时近的先配。配上的两端同一个编号，种名加「/腰 + 两端距离」
     （同一特征里长短不同的是两种，也不与同特征的圆孔混成一种）；配不上的半圆丢掉（开口槽口、圆弧槽不认）。
  3. **计数**：一个腰型孔算一个孔，回执写「H 个孔（含 S 个腰型孔）共 T 种」。
  4. **孔标注**：腰型孔两端都留在种里，已有标注挂在任一端都算整种标过；新标注选这一种最靠左上的那一端圆弧
     `AddHoleCallout2`（SolidWorks 对腰型孔与圆孔同一个接口，规格一次写全），放置同 REQ-003 第 6 条。
  5. **中心符号线**：两端各当一个孔（用户定，DEC-011），同种端头一组线性中心符号线带连接线，按 REQ-005 第 3 条插入，
     但 `InsertCenterMark3` 的第三个参数（槽口样式）必须给 true——给 false 时 SolidWorks 不报错、却把每个端头各建成单个。
     一个腰型孔也有两端，所以总是线性组。插入后一律读回 `ICenterMark.Style` 核对：不是线性组就按 SolidWorks 拆出的单个计数、
     不再补插。标在端头上的旧符号线按 REQ-005 第 2 条删。
  6. **孔位尺寸**：每个腰型孔只取上方那一端的圆心（两端一样高取左端）参加 REQ-006 的分种、链式、阵列与去重；
     连在任一端上的旧线性尺寸都按 REQ-006 第 8 条删。
- 验收：离线用例「slots: …」5 组；真机见 VERIFY-LIVE 第 11–13 步。
- 关联组件：`b-Code/HistoryStrenua/SlotPlanner.cs`、`HoleScan.cs`、`HoleCalloutPlanner.cs`（`Recognize` / `Representatives` / `Count`）
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-008 销钉符号（1.6.0）

- 目的：异形孔向导加了销钉孔，现场图纸却常漏了销钉符号，要一个个补。
- 要求：
  1. 取视图、认孔、同心合并与 REQ-003 第 1–4 条相同。
  2. **销钉孔只认异形孔向导做的**：孔壁所属特征类型 `HoleWzd`，`IWizardHoleFeatureData2.FastenerType2` 是各标准的销钉孔
     （`swWzdHoleStandardFastenerTypes_e` 703–712）。手工切出的孔、腰型孔端头不算。
  3. 一孔一个销钉符号：选孔边 `IDrawingDoc.InsertDowelSymbol`。已有销钉符号（注解类型 10，附着孔边；附着丢了用
     `IDowelSymbol.GetArcPoints` 的圆心，图纸坐标）所在的孔跳过，不删旧的。
  4. 回执说明认出几个销钉孔、新加几个、跳过几个、SolidWorks 拒绝几个；有要加的却一个都没加上时回执失败。
- 验收：离线用例「dowels: …」2 组；真机见 VERIFY-LIVE 第 17 步。
- 关联组件：`b-Code/HistoryStrenua/DowelSymbol.cs`、`DowelPlanner.cs`、`HoleScan.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-009 标注避障（1.6.0）

- 目的：孔标注的文字、孔位尺寸的数字压在别的孔的标注线条上，读不清，要手工一个个挪。
- 要求（用户定：不单独成指令，并进「孔标注」与「孔位尺寸」；范围本视图、只看孔相关）。1.7.0 起受页面「避障」开关控制
  （REQ-011，默认开）；关着时两条指令加完就结束，不读也不挪：
  1. **孔相关注解**：连着孔的孔标注、连着孔边或穿过孔心的线（中心符号线、中心线）的线性尺寸、标在孔上的中心符号线、
     孔上的销钉符号、穿过孔心的中心线。外形尺寸、注释、别的视图不看也不动。
  2. **文字框**：`IDisplayData.GetTextPositionAtIndex` 是左下基线点（图纸坐标），宽 `GetTextInBoxWidthAtIndex`、高
     `GetTextHeightAtIndex`、角 `GetTextAngleAtIndex`（竖直尺寸 π/2，字往 -X 长），四周留白 0.3 mm。
  3. **压到** = 别的孔相关注解的直线（显示数据里的线；销钉符号按圆的八段折线）穿过文字框，或两个文字框相交。
     站在别的尺寸的尺寸线上（共线）也算；自己的尺寸线 / 下划线不算，但孔位尺寸**自己的尺寸界线**算（跨度装不下字时整段滑到界线外）。
  4. **孔位尺寸**：「孔位尺寸」加完尺寸后逐个检查，压着就沿尺寸线方向滑，每步 0.5 mm、先正后负、最远 30 mm，取最近的不压位置；
     不换层。滑到头都压就原样留着。
  5. **孔标注**：「孔标注」加完（或全都已有）后逐个检查视图里的孔标注，压着就换角位：折点离孔心「半径 + 12 / 18 / 24 mm」，
     每档依次左上、右上、左下、右下；挑第一个不压的，都压就挑压得最少且少于现在的，再没有就不挪。文字在折点右侧时
     折点对下划线左端（SolidWorks 自动换引线侧，文字整块随标注刚性平移，下划线比文字长出 1.25 mm）。
  6. 挪完回读核对；回执末尾加「避让挪开 M 个尺寸数字 / 孔标注（K 个找不到空位、原样留着）」，没动就不写。
- 验收：离线用例「clearance: …」3 组（含过渡板真机显示数据）；真机见 VERIFY-LIVE 第 18 步。
- 关联组件：`b-Code/HistoryStrenua/Clearance.cs`、`ClearancePlanner.cs`、`HoleCallout.cs`、`HolePosition.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-010 孔标注全流程（1.6.0）

- 目的：一张图要对每个视图依次按四条孔类指令，太繁琐。
- 要求：
  1. 不用点选视图，范围是**当前图纸页**的全部视图（`IDrawingDoc.GetFirstView` 之后的视图；不切换图纸页，用户定）。
  2. 每个视图依次：销钉符号（REQ-008）→ 中心符号线（REQ-005）→ 孔位尺寸（REQ-006）→ 孔标注（REQ-003）；
     后两步的避障与尺寸链模式照页面开关（REQ-011）。
     顺序用户定；孔标注放最后，避障时尺寸都已在位。
  3. 没引用模型的视图跳过；某一步失败（如找不到基准边）不中断，接着做后面的步骤与视图；取消立即停。全部视图做完指令才结束。
  4. 回执首行「当前图纸页 N 个视图都已做完（K 步没成：…）」，其后每步一行原回执；有步骤失败时回执失败。
- 验收：离线用例「full flow: steps and scope」；真机见 VERIFY-LIVE 第 18–19 步。
- 关联组件：`b-Code/HistoryStrenua/HoleFlow.cs`、`HoleScan.cs`（`SheetViews`、`Scan(view:)`）
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-011 页面开关（1.7.0）

- 目的：避障原先写死在指令里，用户要能关；孔位尺寸要多一种「全部用尺寸链」的标法（DEC-018）。
- 要求：
  1. 两个开关：**避障**（默认开，控制 REQ-009）、**尺寸链**（默认关，控制 REQ-006 第 10 条）。作用于单条孔类指令与全流程。
  2. 指令 `strenua.option.clearance` / `strenua.option.chain`：`value=true|false` 改并存档，省略 `value` 只报当前值，
     别的值拒绝且不改。页面开关拨动走的就是这两条（动作参数 `value={value}`）。
  3. 记在模块数据目录（`IModuleEnvironment.DataDirectory`）的 `options.json`（`{"Clearance":true,"Chain":false}`），
     重启后保持上次；文件不在、读坏了回默认值，缺的项按默认值；写不进去时本轮照样生效，回执注明没记住。
  4. 页面描述里开关的初值取当前值；`strenua.quick.list` 末行报两个开关的状态。
- 验收：离线用例「options: defaults, persistence, commands」「class panels: buttons and switches」；真机见 VERIFY-LIVE 第 20–21 步。
- 关联组件：`b-Code/HistoryStrenua/StrenuaOptions.cs`、`HistoryStrenuaModule.cs`、`StrenuaPage.cs`
- 关联验证：`VERIFY-UNIT`、`VERIFY-LIVE`

### REQ-004 页面

- 要求：Aurora 描述协议 V1，一页 `powersw`（标题 PowerSW，中央，场景 `HistoryStrenua`）。1.7.0 起（DEC-018）没有指令表，
  页面由一行工具条和按类切换的控制面板组成：
  1. **工具条**（一行面板 `quick-toolbar`）从左到右：「浮动」按钮（动作 `strenua.page.float` → `aurora.ui.float name=powersw`，
     需 Aurora 1.30.1+：整页浮成置顶小窗，再点还原）、占位文字「PowerSW · 按住此处拖动」（`flex`，占余宽；
     浮出后按住它拖动整窗——按钮、选择框会吃掉按下）、类选择框（各类名，初值第一类，发布通道 `strenua.class`）、
     「取消」（`strenua.quick.cancel`）。
  2. **控制面板**：切换容器 `class-panels`（`source={selection.strenua.class.value}`），每个类一块面板
     `class-<命令类>`（`case` = 类名）。面板第一行（`even`）是这一类每条快捷指令一个按钮，动作 `strenua.quick.<键>`，
     执行中按钮显示 Aurora 的运行态。「孔」面板第二行是两个开关「避障」「尺寸链」（REQ-011）。
     将来加别的类只加一块面板，工具条不变。
  执行过程与结论只进控制台（`CommandContext.Progress` 与回执），页面上不再有状态格。owner 与场景由指令域推出（`strenua` → `HistoryStrenua`）。
- 验收：离线用例「page owner follows domain」「buttons, actions and commands line up」「toolbar: …」「class panels: …」；
  合同检查的 owner 规则；VERIFY-ACCEPT；VERIFY-LIVE 第 14–16 步。
- 关联验证：`VERIFY-UNIT`、`VERIFY-FULL`、`VERIFY-ACCEPT`

## 系统架构

```
Aurora PowerSW 控制面板按钮 ──strenua.quick.<键>──▶ strenua.hole.callout 等（总线指令）
Aurora 开关 ──strenua.option.clearance / chain──▶ StrenuaOptions（options.json）
                                   │
                           QuickCommandRunner（单并发、取消、执行状态；带上 StrenuaOptions）
                                   │  新建 STA 线程
                           SolidWorksSession.AttachRunning（GetActiveObject）
                                   │
                           SolidWorksApi（运行时加载 Interop，按接口名反射调用，
                                   │   忙时重试 RPC_E_CALL_REJECTED，收工统一释放 COM）
                           HoleFlow（当前图纸页逐个视图，依次调下面四条）
                           HoleScan（取视图 → 取边 → 判孔 / 腰型孔端头 / 销钉孔）→ SlotPlanner（配对）
                             ├─ DowelSymbol（DowelPlanner → InsertDowelSymbol）
                             ├─ CenterMark（CenterMarkPlanner → 删旧 → InsertCenterMark3 线性组 + 连接线）
                             ├─ HolePosition（HolePositionPlanner → 删旧 → Add{Horizontal,Vertical}Dimension2 + 前缀 → Clearance 滑开）
                             └─ HoleCallout（HoleCalloutPlanner → AddHoleCallout2 → Clearance 换角位）
```

| 组件 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| `HistoryStrenuaModule` | 注册指令 | 宿主上下文 | 12 条 `strenua.*` 指令 |
| `StrenuaPage` | 页面描述、动作声明 | 登记表、开关当前值 | JSON |
| `StrenuaOptions` | 避障、尺寸链两个开关，存档到模块数据目录 | 开关指令 | 当前值 |
| `QuickCommandRunner` | 执行编排 | 快捷指令、命令上下文 | 回执 |
| `SolidWorks/*` | 附着与 COM 调用 | 运行中的 SolidWorks | COM 对象 |
| `HoleScan` | 取视图、认孔（两条孔类指令共用） | 活动工程图 | 候选孔边 |
| `HoleCalloutPlanner` | 纯几何：同心合并、分种、孔标注目标 | 候选孔边、已标注孔心 | 标注目标 |
| `SlotPlanner` | 纯几何：腰型孔端头半圆判定、鼓出方向、两端配对 | 合并后的孔 | 带腰型孔编号的孔 |
| `CenterMarkPlanner` | 纯几何：中心符号线分组、要删的旧符号线 | 候选孔边、已有中心符号线 | 组与待删 |
| `HolePositionPlanner` | 纯几何：基准边、链式 / 阵列、按中心线去重、分层放置、尺寸链模式、要删的旧尺寸 | 候选孔边、直边、已有尺寸 | 尺寸与待删 |
| `DowelPlanner` | 纯几何：哪些孔是销钉孔、哪些还没符号 | 候选孔边、已有销钉符号孔心 | 待加的孔 |
| `ClearancePlanner` | 纯几何：文字框、压线判定、尺寸滑开距离、孔标注角位 | 文字框、障碍线条与文字 | 偏移 / 角位 |
| `Clearance` | 读孔相关注解的线条与文字，挪、回读核对 | 视图、孔 | 挪开 / 留着个数 |
| `HoleFlow` | 当前图纸页逐视图串四条孔类指令 | 活动工程图 | 汇总回执 |
| `AnnotationEraser` | 删注解、回读、最多三遍（中心符号线与孔位尺寸共用） | 回读函数 | 删掉 / 剩下个数 |

模块内部类型全部 `internal`，不构成跨模块消费面；跨模块只经总线（指令说明读 `diana.docs.read domain=strenua`）。

## 对外约定（2026-10-02 自原《模块API》移入）

各条指令的参数与示例读注册时的自描述（`diana.docs.read domain=strenua`）；下面是自描述装不下的回执与 Data 形状。

- 共同前提：SolidWorks 必须已在运行，本模块只附着，不启动、不隐藏、不退出它；一次只执行一条快捷指令，第二条直接失败回执「还在执行」。
  执行中经 `CommandContext.Progress` 逐步报告，消费方不必从结论里复述过程。
- 孔类指令 `Data` 为 `null`，结论只在 `Message`（避障那一句只在有挪动时出现；「避障」开关关着时不会出现）：
  - `strenua.hole.dowel`：`视图「X」：D 个销钉孔，新加 N 个销钉符号，M 个已有跳过，K 个 SolidWorks 没有接受。`；没有销钉孔、都已有符号时成功无改动。
  - `strenua.hole.callout`：`视图「X」：H 个孔（含 S 个腰型孔）共 T 种，新加 N 个孔标注，M 种已有标注跳过，K 个 SolidWorks 没有接受，避让挪开 A 个孔标注（B 个找不到空位、原样留着）。`
  - `strenua.hole.centermark`：`视图「X」：H 个孔（含 S 个腰型孔）共 T 种，删掉旧中心符号线 D 个，新加线性带连接线 L 组、单个 S 个，K 个孔 SolidWorks 没有接受。`
  - `strenua.hole.position`：`视图「X」：H 个孔（含 S 个腰型孔）共 T 种，删掉旧位置尺寸 D 个，新加 N 个（阵列标法 P 个；连在中心线上 C 个，其余孔上没有中心符号线、连在孔边上），K 个 SolidWorks 没有接受，避让挪开 A 个尺寸数字（B 个找不到空位、原样留着）。`；
    尺寸链模式下「阵列标法 P 个」写成「尺寸链模式」。
  - `strenua.hole.flow`：首行 `孔标注全流程：当前图纸页 N 个视图都已做完（K 步没成：视图「X」孔位尺寸、…）。`，其后每步一行 `[步骤名] 原回执`；有步骤失败即回执失败。
  - 失败：SolidWorks 未运行 / 未注册；没有打开文档或活动文档不是工程图；60 秒内没点选视图；视图不引用模型；已被取消；旧注解删三遍仍删不掉（此时不重标）；
    孔位尺寸找不到竖直或水平直边做基准；确有要加的却一个都没加上。成功但无改动：视图里没有正对图纸的孔（孔标注另含「孔都已有标注」）。
- `strenua.quick.cancel`：不失败，没有在跑的指令也回成功；被取消的那条回执失败「已取消」，已经加上的标注不回滚。
- `strenua.option.clearance` / `strenua.option.chain`：`Data` 为 `null`；改了回「PowerSW「避障」已打开。」之类，存档失败时在后面注明；
  省略 `value` 回「当前开 / 关」；`value` 不是 true / false 时失败。
- `strenua.quick.list`：`Data` 为 `IReadOnlyList<IReadOnlyDictionary<string,string>>`，每行键 `id`、`title`、`class`、`usage`、`state`、`result`、`time`（`HH:mm:ss`，未执行过为空）；
  `Message` 末行是「避障：开；尺寸链：关」；
  `state` 取值：`就绪`、`附着 SolidWorks`、`等待点选视图`、`识别孔`、`加销钉符号`、`加标注`、`删旧符号线`、`加中心符号线`、`删旧尺寸`、`加尺寸`、`避障`、`完成`、`失败`、`已取消`。
- 界面内部协议 `strenua.ui.describe / actions` 声明 `HiddenReason`，不要跨模块调；页面 owner 与场景 id 为 `HistoryStrenua`，页面 id `powersw`。
  1.7.0 删掉了 `strenua.ui.data`（指令表的取数）。
