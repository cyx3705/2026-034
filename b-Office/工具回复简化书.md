# 工具回复简化书

> 依据：2026-11-04 在 2026-043 总装上修连接、上约束那一轮（约 40 次 Strenua 调用）的真实回执。目标：AI 读一次回执就能做下一步，不用在重复和正常项里找异常。

## 一、问题盘点（按占用排序）

| 工具 | 一次回执体量（估） | 主要毛病 |
| --- | --- | --- |
| `asm.matetree` | 文字约 1 万字 + Data 约 9 千字 × 2 | 36 行逐条列；25 行是同一句「定不死，保持固定不加（能加的只有…剩 3 个自由度（沿 X 移、沿 Z 移…））」；第二、三次重跑把没变的「已有配合，不加」全部再列一遍；子装配零件全路径（`FBT134-…-OS1-1/FBT-134-4P-BLOCK-PT-1@F107`）每行出现；成环断开 18 条长名字连成一行；Data 每行又把文字抄了一遍 |
| `asm.dof` | 文字约 3.5 千字 + Data × 2 | 10 个「固定 无配合」各占一行；每个零件把挂着的全部配合名列出（立柱底板 12 条，其中 9 条是配到它身上的下游配合）；Data 的 mates 列与文字重复 |
| `asm.matelist` | 约 4 千字 | 33 行每行带子装配全路径和空的 error 字段；只想知道有没有报错时全是噪声 |
| `asm.contact` | 文字约 2 千字 + Data 约 3 千字 × 2 | 文字已按对方面合并，Data 还是没合并的逐对行（同一对方面因我这边被槽切成两块出现两次）；直连 MCP 时只回了 Data、总结文字丢了，经 relay 时文字 + Data + structuredContent 三份 |
| `asm.concentric`（预览） | 约 2 千字 | 14 行全是「已有配合定死，不加」；「Ø5、Ø5、…」16 个一样的孔径逐个列 |
| `asm.list` | 约 7 千字 | 43 行每行原点、轴、包围盒，1.39 又加了 matrix 列；摆位时通常只看一两个零件 |
| `asm.interference` | 约 1 千字 | 每次都重报同样 8 条「正常」干涉（6 处脚杯螺纹、2 处模组厂家模型内部） |
| 所有指令 | 每次约 60 字 | 【笔记区·装配】同一条笔记每次调用都带，一轮 40 次 ≈ 2400 字 |
| 跨工具（宿主 / relay） | 每次 × 3 | Data 进了 text 一份、structuredContent 一份，文字里如果也写了就是第三份 |

## 二、通用规则

1. **先结论，后异常，正常只计数。** 第一行回答「成没成、几个、要不要我管」；只逐条列需要动手的（失败、没贴上、过定义、会被拉动）；正常项（贴合、已定死、已有配合）写成一个计数。
2. **同一结论合成一行，按原因分组。** 同一句话出现 3 次以上就改成「原因（n）：名字、名字…」。例：`定不死保持固定（25）：只一个贴合面 21 个，只一个孔 2 个，…`。
3. **重跑只报变化。** 结果与上次相同的项不再列，第一行写「与上次相比：新加 3 条，其余不变」。
4. **名字用短名。** 子装配零件一律 `子装配-1/…/零件-1`（已有 `AsmInterference.Short`），面引用写 `零件-1@F12`；需要全名时放 Data，不放文字。
5. **文字与 Data 不重复。** 文字给人读的结论；Data 只放下一步要用的机器字段（名字、面引用、数值），不放整句。宿主会把 Data 抄进 structuredContent，再进文字就是三份，所以文字里不写 JSON 能表达的明细。
6. **默认有体量上限，明细按需要。** 文字默认不超过约 1500 字；超了就截断并写「…另有 n 项，`detail=是` 看全部」。`detail=是` 才逐条列全。
7. **已知正常项用白名单收起。** 螺纹件进底孔、外购件厂家模型内部干涉，第一次报一次说明，之后只计数「另有 8 处已知正常」。
8. **笔记区只在需要时带。** 同一类笔记在一次会话里第一次调用时带，之后笔记没改就不再带；用户改了笔记再带一次。
9. **数字统一精度。** 长度 0.01 mm、面积整数 mm²、角度 0.01°；不写 `0.971 没贴上` 这种三位小数，除非小于 0.1 mm。

## 三、逐个工具的改法

### `asm.matetree`
- 第一行：`根 L700-1；配上 13 个（33 条配合，全部定死）；保持固定 25 个；撤回 0；成环断开 18 条；连不上 6 个。`
- 逐条只列：本次新加了配合的零件（一行一个：`立柱底板-1 ← FBT134 滑块：重合 + 2 同心，微调 0.04`）、撤回的零件（带原因）。
- 「定不死保持固定」按原因分组计数，各列名字；「已有配合」只计数。
- 成环断开、连不上：只给个数，`detail=是` 才列名字。
- Data：每个配上的零件一行 `{child, parent, mates:[{type, a, b}], dof}`，不放整句。

### `asm.dof`
- 第一行：`固定 10、定死 8、还能动 0。`
- 只逐条列「还能动」「过定义 / 无解」「固定着又和固定件配合」的零件；固定且无配合的只计数。
- 每个零件只列**约束它的**配合（对方已定住的那些），配到它身上的下游配合不列，只写「下游 9 条」。

### `asm.matelist`
- 默认只列有报错 / 警告 / 压缩的配合，其余写「另有 33 条正常」；`detail=是` 列全。
- 按零件对分组：`立柱底板-1 ↔ 8080 立柱：重合、同心 ×2`，比逐条 33 行短一个量级。

### `asm.contact`
- Data 与文字同口径：按「我这边的面组 × 对方面」合并后再出行（与 `ContactPlanner.Lines` 一致）。
- 直连 MCP 也必须带总结文字（这次直连只回了 Data，是缺陷）。

### `asm.concentric`
- 预览默认只列「会加」的对；「已有配合定死」只计数。
- 孔径去重：`16 组 Ø5` 而不是逐个列。

### `asm.list`
- 加 `name=` 片段筛选；默认不出 matrix 列（`detail=是` 或 `name=` 只有一个时才出）。
- 包围盒保留一位小数，原点与包围盒只在 `detail=是` 时都给，默认只给原点和轴。

### `asm.interference`
- 已知正常（螺纹件进底孔、同一外购件子装配内部）收起成计数，只逐条列其余的。

### 长任务的「还在执行」
- 保持现状（一行），但 `quick.last` 取回时套用同样的精简规则，不另起一套。

## 四、验收标准

- 2026-043 同样的流程重跑一遍：贴合树回执文字 ≤ 1500 字、自由度 ≤ 600 字、配合列表（全正常时）≤ 200 字。
- 没有任何一句话在同一个回执里出现 3 次以上。
- 同一个数据在 text 与 Data 里不重复出现。
- `detail=是` 下信息不比现在少。

## 五、不在本模块里改的

- relay 把 Data 抄进 text 和 structuredContent 两份，是宿主 / Diana 的行为，要在宿主那边单独提。
- 笔记区注入在 `QuickCommandRunner`，规则 8 改那里，所有指令一起生效。
